# Production page audit

Audit date: 2026-09-21. This initial assessment was completed before implementation. Statuses below describe the inspected baseline; the implementation and verification sections record subsequent changes. This is a repository assessment, not a legal opinion or certification.

## Verified project and scope

Staff-operated juice-shop POS, not a public online shop. Next.js 16.3.5 App Router, React 19, JavaScript/JSX, MongoDB/Mongoose transactions, Zod, Tailwind/CSS, Sonner, Recharts, Dexie and Playwright (`package.json`). ADMIN and CASHIER accounts are provisioned by administrators; JWT sessions use the HTTP-only `karikku_session` cookie, 12-hour expiry and database token-version revocation (`src/models/User.js`, `src/lib/auth.js`, `src/lib/jwt.js`, `src/services/auth.js`, `src/services/admin.js`).

Payments are cashier-recorded Cash/UPI/Card allocations, not gateway charges. Checkout recalculates and persists sales transactionally with idempotency; refunds/cancellations change recorded status and require an open day (`src/services/sales.js`, `src/lib/payments.js`, `src/models/Sale.js`). No subscriptions, shipping, public registration, community, email/SMS delivery, payment webhooks, or native application package were found in the tracked source/dependencies/routes.

Repository scan covered all tracked source areas: app entrypoints/routes/layouts, all models/services and validation/auth helpers, component/workspace and hook patterns, cart context, offline storage/service worker, public assets/manifest, configuration/environment example, README, scripts and tests. Generated build directories, dependency source unrelated to framework guidance, secret environment values, and production database contents were excluded. No production data was modified. Existing Next.js local guides for error boundaries, not-found and proxy were read; 16.3 supports `retry()` to re-fetch an error boundary.

## Data and integration inventory

- MongoDB: staff name/username/password hash/role/lockout metadata; customer name/phone/optional birthday/loyalty; sale customer/cashier/business snapshots and item notes; expenses, session operators and cash movements. See all `src/models/*.js`. No card PAN/CVV collection found; recorded payment method is not payment processing.
- Browser: `karikku_session` is HTTP-only, SameSite=Lax, Secure in production, 12 hours. Optional `karikku_drive_connect` OAuth state cookie is HTTP-only, SameSite=Lax, production Secure, path `/api/backups`, 10 minutes. Dexie database `karikku-pos-offline` stores catalog/settings in active caching code; other tables/queue scaffolding exist but no checkout enqueue caller found. Static asset Cache Storage via `public/sw.js`. Cart is React memory; no durable recovery promise.
- Integrations in source: MongoDB hosting unspecified; Cloudinary product-image uploads (`src/lib/cloudinary.js`), optional Google Drive OAuth/manual backups (`src/services/google-backup.js`), local file/download access for backups (`src/components/settings/backup-settings.jsx`). Installed code does not prove which integrations are deployed or enabled.
- No analytics/ad tracking, email, SMS, push or geolocation request found. Camera/microphone/geolocation are disabled by `next.config.mjs`. Product uploads and file downloads are real. No i18n or dark-theme switch found; preserve existing English/light interface.
- Admin exports and backups exist; recovery/deletion, operational retention, hosting access/logs, live TLS and third-party agreements require owner/deployment verification. Do not publish blanket encryption/backup/compliance claims.

## Remaining risks and owner decisions

1. The full-system regression suite is not green. Its remaining legacy discount/setup expectations need reconciliation with the accepted global discount contract before claiming whole-project regression coverage; downstream checks remain unverified.
2. Privacy, terms, refunds/cancellation/returns, acceptable use, security/disclosure, accessibility statement and DPA/deletion applicability remain blocked by the consolidated owner questions above. No legal placeholder was published. Professional review remains necessary.
3. Offline support is a catalog/static-cache foundation. It does not save sales offline, recover carts after navigation, or guarantee all queued data synchronized. The fallback requires a prior successful online service-worker installation.
4. The permission page is a redirect-based explanatory state; APIs independently enforce actual HTTP 403. Next streamed redirects/not-found responses can have HTTP 200 while delivering the intended client state.
5. Maintenance requires the deployment owner to set the flag consistently and restart instances; verify reverse-proxy behavior and reconcile requests already in flight. No deployment occurred.
6. Global root fallback is implemented and compiled, but not tested with a root-layout exception. Ordinary layout/server failure and retry/help behavior were tested. Existing broader accessibility, shared-device cache ownership, session cross-tab behavior and live provider operations require further focused review; no conformance/security certification is asserted.

User-facing result: Profile options now opens Your account, Help and setup, and Cookies and browser storage. Login offers password assistance and session-expiry context. Staff get clearer permission, missing-page, failure, offline and empty-search recovery. Legal publication and full regression closure remain outstanding.
